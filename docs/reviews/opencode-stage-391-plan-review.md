## Minor Findings

**M1 — Recovery matrix gap: `live_moving` with live present and backup absent.**
The recovery matrix (design lines 380-391) tabulates "`live_moving`, live missing, backup present → restore backup," but does not explicitly cover the double-fault state reachable when the live→backup rename fails *and* the `_replace_phase(READY)` journal rollback also fails (plan lines 1162-1171 raise `RowOnePublishCleanupPendingError`, leaving the journal at `LIVE_MOVING` with the old live still in place and no backup). The recovery dispatcher's `else` branch (plan lines 1308-1310) correctly handles this by keeping live and cleaning the stage/journal, and the general principle at design line 377 ("favors the previous version when a backup exists") covers the intent. The named test `test_recovery_keeps_old_live_before_backup_move` (plan line 1267) only covers `staging`/`ready` phases. Recommend adding one matrix row or one parametrized recovery test that seeds `phase=live_moving`, live present, no backup, and asserts live is kept and owned stage/journal are removed.

**M2 — `_begin_staging` does not clean up a stage directory if owner-marker write fails.**
`_begin_staging` (plan lines 1320-1326) writes the journal, then `mkdir` the stage, then writes the owner marker. If `_write_owner_file` raises after the directory exists, the outer handler calls `_cleanup_after_handled_failure`, whose preflight (plan lines 1349-1352) requires the stage to carry the matching regular owner marker. An ownerless stage therefore raises `RowOnePublishAmbiguousStateError` and is left in place with its journal, requiring manual operator inspection. This is safe (nothing is deleted unsafely) but not self-healing for that narrow half-build case. Recommend either cleaning the just-created stage directory inside `_begin_staging` before re-raising, or explicitly documenting that an owner-write fault produces a recoverable ambiguous state rather than a fully cleaned one.

**M3 — `publish_latest_row_one_site` returns a result whose paths point at the renamed-away staging directory.**
The public entry point (plan lines 1433-1469) returns `result` unchanged from the render callback. After commit, `result.output_dir` and `result.index_path` reference the stage path that no longer exists (it was renamed to live). The `render_row_one_site` dispatcher (plan lines 1596-1611) correctly ignores those fields and rebuilds a `RowOneRenderResult` with logical paths, so no integration test observes the staleness. A direct caller of `publish_latest_row_one_site`, however, would see non-existent `output_dir`/`index_path` values. Recommend either rebasing the returned result to logical paths inside `publish_latest_row_one_site`, or adding a docstring note that callers must rebase `output_dir` and `index_path` from the logical output.

**M4 — `_remove_publish_path` silently no-ops on special files.**
`_remove_publish_path` (plan lines 1023-1027) tests `is_symlink() or is_file()` then `is_dir()`; a FIFO, socket, or device falls through both branches and the call returns without removing or raising. The cleanup preflight is supposed to reject such objects before any mutation, so reaching this path indicates a logic error elsewhere. A defensive `else: raise RowOnePublishAmbiguousStateError(...)` would turn a silent skip into a fail-fast signal during development.

**M5 — `clean_row_one_site_children` becomes internal dead code.**
After Task 4, `latest_only=True` routes through the publisher and `latest_only=False` writes in place without calling `clean_row_one_site_children`; the only remaining caller is `tests/test_row_one_render.py:20482`. The plan (design lines 151-153) says the function "remains available for the in-place behavior" and that its check logic is extracted into a shared read-only helper. The shared helper is the right design, but retaining the public mutating function with no internal caller is a minor API-surface debt. Recommend a one-line note in `render.py` clarifying that `clean_row_one_site_children` is retained as a public utility for external/latest-only-False callers and is not invoked by the staged publisher.

**M6 — First-rename-failure error is re-wrapped by the outer handler, slightly mischaracterizing a commit-time failure.**
`_commit_existing_publish` (plan lines 1174-1176) raises `RowOnePublishError("ROW ONE could not move the live site; the previous site remains available")` after rolling the phase back to `READY`. Because `RowOnePublishError` is not in the bypass list (plan lines 1453-1459), the outer handler re-wraps it as "ROW ONE staged publish failed before commit." The design (design lines 448-458) asks errors to distinguish "first or second rename failure." The second rename is properly distinguished via `RowOnePublishRestoredError`/`RowOnePublishRollbackError`; the first-rename distinction is collapsed into the generic pre-commit wrapper. The message is safe (no tokenized paths) and could be bypassed directly. Recommend either adding this specific sanitized message to the bypass list, or accepting the collapse with a code-comment noting the first-rename detail survives in `__cause__`.

**M7 — `KeyboardInterrupt` during the live→backup rename can be demoted when the READY-phase rollback also fails.**
In `_commit_existing_publish` (plan lines 1162-1171), if `move_error` is `KeyboardInterrupt`/`SystemExit` and the `_replace_phase(READY)` write also raises, the handler raises `RowOnePublishCleanupPendingError(...) from journal_error`; the original control-flow exception survives only as `__context__`. This is a narrow double-fault and the resulting state is safe (journal pinned at `LIVE_MOVING`, live untouched, recovery handles it via M1's path). Recommend re-ordering the handler to check `isinstance(move_error, (KeyboardInterrupt, SystemExit))` and re-raise before attempting the journal rollback, matching the pattern used in `_commit_first_publish` (plan lines 1229-1230).

## Verification Of User-Requested Surfaces

- **Filesystem transaction correctness:** atomic journal writes via exclusive temp + `os.replace` + `fsync` (plan lines 650-698); `os.replace` for all directory renames on the same filesystem (plan lines 1019-1020); validation reads disk JSON, not in-memory payloads (plan lines 969-985).
- **Empty stable-lock crash recovery on POSIX/Windows:** POSIX `fcntl.flock(LOCK_EX|LOCK_NB)` and Windows `msvcrt.locking(LK_NBLCK, 1)` both lock an empty file; metadata is initialized only after the OS lock is held (plan lines 760-800); the empty-file recovery test is explicit (plan lines 741-752). Sound.
- **No-follow ownership:** `O_NOFOLLOW` where available with lstat/fstat identity fallback for lock, journal, temp journal, and owner paths (plan lines 661-663, 697-713, 797-800); symlink/directory/FIFO/special-file in those roles are rejected without being followed, overwritten, or deleted (plan lines 572-578). Sound.
- **All-artifact cleanup preflight:** `_preflight_cleanup_artifacts(transaction, *, published)` validates canonical journal, phase, owner, stage/backup, and the complete temporary-journal set as one read-only pass before any mutation (plan lines 1339-1357). Sound.
- **First/existing rollback for rename and journal-write failures:** first-publish move failure leaves no partial live (plan lines 1205-1233); validation/`published`-write failure moves token-owned live back to stage and cleans (plan lines 1213-1228); existing-publish live→backup failure rolls phase back to `READY` (plan lines 1162-1176); stage→live/validation/`published`-write failures call `_rollback_existing_publish` which preflights, moves new live aside, restores backup, revalidates, and cleans (plan lines 1242-1259). `live_backed_up` and `published` journal-write failures are handled in-invocation, not deferred (plan lines 1196-1199, 1088-1093). Sound.
- **Every recovery phase:** the dispatcher at plan lines 1301-1310 plus the named tests at plan lines 1266-1278 cover `staging`/`ready`, `live_moving`, `live_backed_up`, pre-`published`, first-publish, `published` valid, `published` invalid, owner-removed `published`, unrelated-only, marker-only, index-only, and ambiguous/malformed. (M1 notes the one gap.)
- **Unrelated child and root metadata preservation:** regular files via `copy2(follow_symlinks=False)`, directories via `copytree(symlinks=True, copy_function=copy2)`, symlinks recreated from `os.readlink` (plan lines 893-907); root mode/timestamp applied via `copystat(follow_symlinks=False)` after render and before `READY` (plan lines 908-916, 1450). Sound.
- **Symlink outputs:** logical symlink preserved; physical target resolved for renames; loop/non-directory rejected; dangling symlink allowed (plan lines 596-618, design lines 114-124). Sound.
- **Ordinary error sanitization:** ordinary failures wrapped as `RowOnePublishError` with concise message and original as `__cause__`; rollback/cleanup-pending/ambiguous errors retain operator paths (plan lines 1460-1478, design lines 448-466); CLI tests assert tokenized stage basenames, tokens, and physical targets do not leak while retained recovery paths remain visible (plan lines 1632-1647).
